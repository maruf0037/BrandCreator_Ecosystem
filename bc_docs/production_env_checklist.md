# BrandCreator Ecosystem - Production Environment Checklist

This checklist serves as a comprehensive guide for auditing, configuring, and verifying the environment variables and credentials of the **BrandCreator Ecosystem** prior to promoting the services to the production environment.

---

## 📋 1. Required Backend Environment Variables (`bc_engine/.env`)

Configure the production backend variables securely on the server. Confirm that every key has been provisioned:

| Variable Name | Required Value / Format | Validation Rule / Purpose |
| :--- | :--- | :--- |
| **`NODE_ENV`** | `production` | Enforces production optimizations, suppresses verbose stack traces, and enables secure cookie policies. |
| **`PORT`** | `5000` (or custom internal port) | Port on which the background Express engine process will bind and listen. |
| **`FRONTEND_URL`** | `https://brandcreator.company.com` | Absolute public URL of the storefront client (used for CORS safety rules). |
| **`SESSION_SECRET`** | *[Cryptographically Secure 64-char Hex]* | Cryptographic key utilized to sign session cookies. Generate via: `node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"`. |
| **`SQL_SERVER`** | `10.0.x.x` (or `db.company.internal`) | Network address/IP of the production MS SQL Server instance. |
| **`SQL_DATABASE`** | `BrandCreator_HUBDB` | Name of the primary double-ledger database. |
| **`SQL_USER`** | `BrandCreator_AppUser` | The database login role specifically created for application use. |
| **`SQL_PASSWORD`** | *[Strong Secure Password]* | Complex SQL server authentication password for the application user. |
| **`SQL_ENCRYPT`** | `true` | Enforces TLS encryption on all data traffic moving between Express and SQL Server. |
| **`SQL_TRUST_CERT`**| `false` (or `true` if self-signed) | Set to `false` in environments with a trusted CA, or `true` if utilizing local self-signed VM certificates. |
| **`GOOGLE_CLIENT_ID`**| `[Client-ID-Hash].apps.googleusercontent.com` | The Google Cloud Console public client identifier for SSO SSO authentication. |
| **`GOOGLE_CLIENT_SECRET`**| `GOCSPX-[Google-Client-Secret-Hash]` | Secret credential key generated by Google Cloud Console for OAuth validations. |
| **`GOOGLE_CALLBACK_URL`**| `https://brandcreator.company.com/api/auth/google/callback` | The absolute public endpoint where Google redirect handles login data. |
| **`WEBHOOK_SECRET`** | *[Cryptographically Secure HMAC Token]* | Shared secret used to decrypt and verify the authenticity of bKash/Nagad callback payloads. |
| **`GEMINI_API_KEY`** | *[Google Gemini API Key]* *(Optional)* | Production API Key required to run the automated description enrichment queues. |

## 🔑 3. Google OAuth Production Credentials Setup

Ensure the Google Cloud Project credentials are configured to permit production login redirection:

1. **Access Google Cloud Console**:
   * Navigate to the *APIs & Services -> Credentials* panel.
2. **Configure the OAuth Consent Screen**:
   * Set User Type to **External**.
   * Fill in support email, app logo, and authorized domains matching `brandcreator.company.com`.
3. **Configure the Web Client Credentials**:
   * Set Application Type to **Web application**.
   * Name: `BrandCreator Production Storefront`.
   * **Authorized JavaScript origins**:
     * `https://brandcreator.company.com`
   * **Authorized redirect URIs**:
     * `https://brandcreator.company.com/api/auth/google/callback`
4. **Acquire Credentials**:
   * Securely copy the generated **Client ID** and **Client Secret** into your server's backend `.env` variables.

## 🔄 4. Cryptographic Secret Rotation Checklist

To maintain compliance and mitigate token compromises, execute a secret rotation cycle every **90 days**:

- [ ] **Google OAuth Client Secret**:
  * Generate a new secret key inside the Google Cloud Console.
  * Update `GOOGLE_CLIENT_SECRET` in `bc_engine/.env`.
  * Perform a graceful rolling restart of the backend Node service.
  * Delete the deprecated secret version in Google Console once service logs show clean authentications.
- [ ] **Session Signing Cookie Keys**:
  * Generate a new 64-character hex key.
  * Update `SESSION_SECRET` in `bc_engine/.env`.
  * Gracefully restart the service. *(Note: This will securely sign out active operator sessions, requiring a fast re-login)*.
- [ ] **Webhook Gateway Secrets**:
  * Execute zero-downtime webhook key rotations via the administrative endpoint:
    ```bash
    POST /api/admin/secrets/webhook/rotate
    Headers:
      x-user-email: md.marufalrashid@gmail.com
      x-user-role: SuperAdmin
    Payload:
      {
        "newKeyId": "wk_2026_09",
        "newSecret": "NEW_CRYPTOGRAPHIC_HMAC_SECRET"
      }
    ```
  * Confirm active key version activation by requesting `/health/deep`.

## 🛡️ 5. SQL Server Least-Privilege User Setup

**NEVER** utilize the SQL Server `sa` (System Administrator) account for production application connections. Implement a least-privilege user pattern:

```sql
-- 1. Create Login on SQL Server Instance
USE [master];
CREATE LOGIN [BrandCreator_AppUser] 
WITH PASSWORD = 'YourStrongSecureProductionSQLPassword', 
DEFAULT_DATABASE = [BrandCreator_HUBDB], 
CHECK_EXPIRATION = ON, 
CHECK_POLICY = ON;

-- 2. Create User inside primary Database
USE [BrandCreator_HUBDB];
CREATE USER [BrandCreator_AppUser] FOR LOGIN [BrandCreator_AppUser];

-- 3. Grant Explicit CRUD permissions on inventory schemas
GRANT SELECT, INSERT, UPDATE, DELETE ON dbo.Products TO [BrandCreator_AppUser];
GRANT SELECT, INSERT, UPDATE, DELETE ON dbo.InventoryLedgers TO [BrandCreator_AppUser];
GRANT SELECT, INSERT, UPDATE, DELETE ON dbo.InventoryTransactions TO [BrandCreator_AppUser];
GRANT SELECT, INSERT, UPDATE, DELETE ON dbo.Orders TO [BrandCreator_AppUser];
GRANT SELECT, INSERT, UPDATE, DELETE ON dbo.OrderItems TO [BrandCreator_AppUser];
GRANT SELECT, INSERT, UPDATE, DELETE ON dbo.OutboxEvents TO [BrandCreator_AppUser];
GRANT SELECT, INSERT, UPDATE, DELETE ON dbo.OutboxAttempts TO [BrandCreator_AppUser];
GRANT SELECT, INSERT, UPDATE, DELETE ON dbo.WebhookReceipts TO [BrandCreator_AppUser];
GRANT SELECT, INSERT, UPDATE, DELETE ON dbo.SecretVersions TO [BrandCreator_AppUser];

-- 4. Grant EXECUTE permissions on Stored Procedures
GRANT EXECUTE ON dbo.sp_InventoryApplyTransaction TO [BrandCreator_AppUser];

-- 5. Revoke general structural modifications
DENY ALTER TO [BrandCreator_AppUser];
DENY DROP TO [BrandCreator_AppUser];
```

## 🧪 6. Pre-Deployment Env Validation Commands

Run these verification commands on the production server host to audit the environment prior to service activation:

1. **Verify No `.env` Files Tracked in Git**:
   ```bash
   git status --ignored
   ```
   *Ensure that `.env` is listed strictly under ignored, untracked files.*

2. **Verify Node Production Environment**:
   ```powershell
   [System.Environment]::GetEnvironmentVariable("NODE_ENV", "Process")
   ```
   *Should output `production`.*

3. **Verify TCP Port availability (Ensure Port 5000 is clean)**:
   ```powershell
   Get-NetTCPConnection -LocalPort 5000 -ErrorAction SilentlyContinue
   ```
   *Should return empty, indicating port 5000 is clean and ready for process binding.*

4. **Verify Direct Local Database Connectivity**:
   Ensure connection parameters resolve cleanly by attempting to connect internally via SQLCMD:
   ```cmd
   sqlcmd -S localhost -U BrandCreator_AppUser -P YourStrongSecureProductionSQLPassword -d BrandCreator_HUBDB -Q "SELECT @@VERSION;"
   ```
   *Should successfully return SQL Server engine version metadata without network connection errors.*
